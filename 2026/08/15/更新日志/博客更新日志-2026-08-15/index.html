博客更新日志 — 2026年8月15日

今天主打一个”既要抓 bug 又要开新坑”。音乐播放器又出幺蛾子了——歌词跟自定义胶囊 UI 玩起了”跷跷板”，一个出现另一个就消失。本小姐本来只想把这个 bug 摁死，结果摁着摁着，手一滑，又给导航栏加了个新玩具：漫步。啧，这双手它有自己的想法。

🎵 音乐播放器：歌词”诈尸”案

现象：诡异的跷跷板

有朋友反馈，导航栏那个胶囊播放器会莫名其妙消失。更邪门的是，它跟歌词玩起了”此消彼长”——歌词一出现，UI 就消失；UI 一出现，歌词就死活不出来。两个人像在玩跷跷板。

最气人的是：本小姐自己电脑上几乎复现不出来，朋友电脑上却稳定复现了两三次。这种”你那边有问题、我这边好好的”的 bug，简直是程序员的梦魇。

排查：先抓外观，再挖根因

第一层线索：播放器处于 fixed 模式（左下角固定 + 折叠按钮）。查 APlayer 源码发现，fixed 模式下的歌词 .aplayer-lrc 和播放器本体是两个各自独立的 fixed 层：

  • 歌词层：position: fixed; bottom: 10px; z-index: 98
  • 播放器 body：position: fixed; z-index: 99

两个层叠在左下角同一位置，z-index 差 1——谁在上谁可见。这就是”跷跷板”的物理原理。而 APlayer 的源码规则是：只有 lrcType && !fixed 才让歌词”内嵌”进播放器；一旦 fixed，这条路直接被堵死，歌词只能走”独立层”这条邪道。

但等一下——这只是解释了两个层为什么打架，还解释不了”为什么时灵时不灵”。真正的病根藏得更深：

病根：一个 6 秒的计时炸弹

之前的 music.js 是这么隐藏 APlayer 引擎的：setInterval 轮询检测 aplayer-fixed 这个 class 出现，出现后立刻 engine.style.display = 'none' 把引擎藏起来。但这个轮询有上限——attempts > 30（约 6 秒）就放弃。

问题来了：朋友网络慢，歌单接口（MetingJS 的异步 XHR）要 6 秒以上才返回。于是隐藏逻辑被跳过了，整个 fixed 播放器（连歌词层一起）原样露出来。本小姐自己本地部署，接口秒回，所以从来不触发。

一个”看网络脸色”的 bug，本地不触发、线上才炸——排查全靠脑补和朋友挑刺。

修复：不靠时机，靠声明

想通之后本小姐悟了：凡是靠 JS 掐时机去隐藏的，迟早会翻车。 于是把策略整个翻过来——不靠时序，靠 CSS 声明式隐藏：

  1. 删掉 music.js 里那行 engine.style.display = 'none'（6 秒计时炸弹，拆了）
  2. 在 inject.head 里加 CSS，只隐藏 .aplayer-body / .aplayer-list / .aplayer-notice / .aplayer-miniswitcher，唯独保留 .aplayer-lrc 歌词层

效果：歌词层稳定显示在底部，播放器主体不再”诈尸”，自定义 UI 稳如老狗。CSS 天生就比 JS 可靠，因为它不跟你玩什么”等接口、掐时间”。

🚶 新功能：漫步（随机文章）

需求

导航栏加个「漫步」按钮，点开能选「全部 / 各一级分类」，然后随机跳到该范围内的一篇文章。就像……在博客里散步，走着走着随机推开一扇门。挺浪漫的，本小姐喜欢这个名字。

总之拍板了几个细节：嵌入导航栏菜单（复用 site-page 样式）、图标用 fa-dice（骰子，掷骰子撞缘分）、排除当前页、面板”全部”那一栏不显示篇数。

实现：服务端喂数据，客户端掷骰子

两个新文件，分工明确：

  • scripts/wander.js（服务端）：hexo.model('Post').toArray() 拿全站文章，生成一份 {posts:[{path,title,cat}], categories:[...]} 的 JSON，通过 after_render:html filter 塞进所有页面的 </head> 前。分类按篇数降序排。
  • source/js/wander.js（客户端）：读数据 → 往 #nav .menus_items 插「漫步」菜单项 → 点开弹面板 → 随机跳转。pjax:complete 时重新插按钮（导航栏随 PJAX 刷新）。

踩坑：中文 URL 的 404 陷阱

这是今天最阴的一个坑。post.path 返回的是没编码的中文路径，长这样：

直接拿去 location.href 跳转？404。因为浏览器地址栏要的是编码后的 URL：

解法：用 hexo.extend.helper.get('url_for') 把 path 转成编码后的 URL。一行 helper，救了整个功能。本小姐差点在”为什么跳转都是 404”上怀疑人生（果然还是中文路径的锅）。

还有个小坑：判定”一级分类”要看 post.categories.data 里 !c.parent 的项——parent 为 null 是一级，有 parent id 的是二级。不看源码谁知道这茬。

排除当前页的小心机

“排除当前页”听着简单，做起来有个坑：路径可能带编码、可能带 index.html 后缀、可能有尾斜杠，各种形态。于是写了 normKey() 先把路径 decode、去掉 index.html 和尾斜杠再比较。不然就会出现”明明就是这页却还随机到它”的尴尬。

顺带清点了一下家底

目前全站 70 篇文章：学习笔记 45 篇、小说 17 篇、博客相关 8 篇，没有未分类的孤儿。这么一看，小说区还挺……需要浇灌的。

🎨 样式拉锯战：一个面板改了三轮

新功能上线后，最磨人的不是功能，是好看。漫步面板来来回回拉锯了好几轮，本小姐记录在案，供后人（也就是明天的自己）引以为戒：

第一轮：圆角 + 阴影统一

本小姐一眼看出「文章」下拉菜单是方角 + 有阴影，跟播放器、漫步面板的圆角风格不搭。于是：

  • 给 .menus_item_child 加 border-radius: 8px; overflow: hidden（主题标准圆角，overflow 让子项 hover 背景也变圆）
  • 播放器和漫步面板的阴影从 0 4px 24px rgba(0,0,0,0.12)（太淡）统一成主题同款 0 5px 20px -4px rgba(0,0,0,0.5)

第二轮：颜色走主题变量

第一轮改完，本小姐又发现漫步面板颜色写死了（#fff / #333），切明暗主题不跟着变。于是把颜色全部换成主题变量：背景 var(--sidebar-bg)、文字 var(--font-color)、hover var(--text-bg-hover)，圆角统一 8px。宽度改成 max-content 自适应。

第三轮：字号 + 定位

这轮最扎心。本小姐一看，面板字体比「文章」菜单大两倍，而且定位方向反了。

一查，血压上来了：

  • 字号：html 根字号 20px，body 是 --global-font-size（14px），#nav 是 1.3em，.site-page 是 0.78em——层层折算下来，「文章」菜单子项实际是 14px。而 wander.js 写的是 font-size: 1rem，相对 html 的 20px，直接渲染成 20px。大了一倍多。
  • 定位：主题 .menus_item_child 是 right: 0（右边缘贴齐父菜单项），本小姐误写成了左对齐，方向整个反了。

改：字号 1rem → var(--global-font-size)；定位改成”面板右边缘贴齐按钮右边缘”。

就一个 150px 的小面板，改了字号、颜色、宽度、阴影、圆角、定位、篇数……七处。本小姐现在深刻理解了什么叫”功能五分钟，打磨两小时”。

🧍 看板娘：台词字号调小

最后一个小改动：看板娘（oh-my-live2d）的台词字号偏大，从默认 18px 调到 14px，跟全局字号统一。

排查发现台词默认字号 fontSize: "18px" 写死在它内部默认样式对象里，tips.style 配置只会浅合并覆盖——之前只改了 width/height/top/left，没碰字号。补上 fontSize: '14px' 就好。

小改动，但看板娘说话终于不显得那么”吼”了。

还不快夸本小姐温柔，哼。

📋 验证清单

  • hexo generate 成功，零报错
  • 播放器歌词层稳定显示，自定义胶囊 UI 不再消失
  • wander-data 70 条数据正确注入，/js/wander.js 已引用
  • 两脚本 node --check 语法通过
  • 漫步面板颜色随主题变量切换，圆角/阴影统一
  • 漫步面板字号 14px、右对齐，与「文章」菜单一致
  • 看板娘台词 14px
