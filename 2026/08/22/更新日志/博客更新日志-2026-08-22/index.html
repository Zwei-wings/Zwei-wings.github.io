博客更新日志 — 2026年8月22日

今天本小姐做了件特别有”仪式感”的事——给南院的 OC 角色们配上声音。光有人设图、基础信息、出身背景还不够，一个角色要”活”起来，总得能开口说话吧？于是从零搭了个配音播放条，结果这玩意儿让本小姐改了整整四版……从手写 HTML 到标签插件，从没音量到有音量，从 emoji 丑图标到矢量 SVG。算了，好看就行，过程不重要（咬牙）。

另外还把标签插件的速查文档整理进了使用指南，顺手把积压已久的改动全推上了仓库。

🎙️ 南院 OC 配音播放条：一个功能改了四版

起因

南院 OC 专栏现在有 14 个角色（专栏 1~4 分别是 3、5、2、4 个）。每个角色都有标题、基础信息表、人设图、细节和出身背景，结构挺完整。但本小姐总觉得——没有声音的角色，只有半条命。

于是决定：给每个角色插一条配音样本。

方案：音频怎么放

先定了个干净的方案：

  • 音频统一放 source/audio/，随 hexo g 复制到 public、随 hexo d 部署
  • 引用路径 /audio/南院-角色名.mp3，不走人设图那种外链目录
  • 命名规范 南院-角色名.mp3
  • mp3 是二进制，Hexo 原样复制，不用动 skip_render

第一版：手写 HTML

最开始用的是原生 <audio> 标签，每个角色一条独立播放条。能响，但——丑，而且每角色要贴 6 行 HTML。本小姐一边写一边皱眉：这要是写 14 个角色，手都要断了。

第二版：胶囊播放条（台词引述）

于是做了一版「台词引述」风格的定制播放条，三个文件联动：

  1. source/css/custom.css：.oc-voice 胶囊样式——播放键 + 角色名 + 波形 + 时长 + 台词引述，还有 [data-theme=dark] 深色适配
  2. source/js/oc-voice.js：事件委托管播放/暂停、三角↔暂停图标切换、时长自动读取、同屏只播一个、PJAX 兼容
  3. _config.butterfly.yml 的 inject.bottom 引入脚本

好看是好看，但 6 行 HTML/角色的门槛还在。

第三版：标签插件

这时候本小姐悟了——都搭了这么多自制标签了，配音凭什么不能也是标签？于是新建 scripts/voice.js，注册了 {% voice %} 标签：

音频自动补 /audio/ 前缀，台词可选，输出和 .oc-voice 的 CSS/JS 匹配的单行 HTML，还带 escapeHtml 转义。一行标签，全搞定。这才是给人用的东西。

第四版：音量 + 颜值

插上之后发现两个问题：音量太重（audio 默认 1.0 震耳朵）、音量控件丑（emoji 🔊 + 浏览器默认滑块）。

先加音量：默认 0.7，跟音乐播放器对齐；每个角色各调各的，独立记忆到 localStorage。静音按钮切换 muted。

再整容：把 emoji 换成两个内联 SVG（有声喇叭 / 静音喇叭，Material 图标，fill: currentColor 由 CSS 控色）；滑块改 -webkit-appearance:none + 圆形橙色 thumb，轨道用 CSS 变量适配明暗主题；还用 linear-gradient 动态填充已播放部分。移动端 ≤600px 直接藏掉滑块，简洁。

至此调用链完整闭环：文章写 tag → voice.js 出 HTML → custom.css 定样式 + oc-voice.js 管交互。14 个角色，一人一行，优雅。

📚 标签插件速查，并入使用指南

之前的《hexo 基础命令行》这篇文章，本小姐觉得应该升级成一本真正的「使用指南」——毕竟现在博客攒了这么多自制标签，不整理一份速查，以后自己都会忘。

于是把标签插件速查并了进去，文件重命名为 博客日常使用指南.md（front-matter 的 title、description、文内 H1 一起改，date 保持 2021-01-17 不顶到首页）。结构变成：## 基础命令行 + ## 标签插件速查。

踩坑：正文写 &#123;% %&#125; 会被真解析

这个坑值得重点记一笔，是 Hexo 的通用陷阱：

在 md 正文/标题里直接写 {% note %} 这类字面符号，会被 Hexo（nunjucks）当作真实 tag 解析 → 直接报 unknown block tag: endxxx。

更坑的是：Hexo 的 tag.js 只保护 HTML <code> 标签里的 {}，**不保护 markdown 代码块 **。也就是说，你在 代码块里写 {% voice %} 想展示字面写法？照样被解析，照样报错。

解法：改用「活示例」——直接写真实标签让它渲染出来（网页看效果、源码看写法），绕开字面符号展示。特殊标签（mermaid 主题没开、checkin_full_page 渲染太大）就一句话文字说明。实测 note/tabs/timeline/hide/btn/link/voice/checkbox/btns/gallery/inlineImg 全部正确渲染，HTML 无残留 {%。

📦 提交推送源码仓库

最后把这段时间攒下的改动全提交了——除了今天的配音功能，还有积压已久的新文章（OC 专栏 15、世界观展示 89、触手君 20~22 章、about 图片等）。

处理细节：本地临时脚本 _extract_tags.py（读 public/tags 提取词云数据）加入 .gitignore，不提交。全量 git add -A + commit（5211cfd，55 个文件，+1908/-207）+ git push origin main 成功。

留了个尾巴

提交时发现音频命名是 audio-1/2/3.mp3 + 同名 .wav 双份——**没按约定的 南院-角色名.mp3**，而且 wav 体积偏大、不适合网页。这个后面 hexo d 之前得处理一下：是只留 mp3，还是改名对齐角色。本小姐先记在小本本上。

📋 验证清单

  • npx hexo g 零报错（含清 db.json 后的全量重渲染）
  • {% voice %} 标签正确输出播放条 HTML
  • 音量默认 0.7、独立记忆、静音切换正常
  • SVG 喇叭图标无 emoji 残留，滑块明暗主题适配
  • 标签速查 10+ 标签全部正确渲染，HTML 无残留 {%
  • 源码仓库推送成功（5211cfd）
